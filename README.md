# Манифест «Искусственный интеллект — каждому студенту МГУ»

Здесь лежат текст манифеста и всё, что нужно для сбора подписей: сайт с
текстом и кнопкой «Подписать», PDF, который сам обновляется с каждой новой
подписью, и автоматика на GitHub Actions.

- **Текст** — [`text/manifesto.md`](text/manifesto.md), приложение с оценкой
  ресурсов — [`text/appendix.md`](text/appendix.md).
- **PDF** — [`manifesto.pdf`](manifesto.pdf). Это снимок без подписей; живая
  версия со списком лежит на сайте.
- **Список подписей** — [`signatures.csv`](signatures.csv). Пока пуст.

## Как это устроено

```
                  сайт: текст, PDF, список подписей
                                  │
                             «Подписать»
                  ┌───────────────┴───────────────┐
                  ▼                               ▼
            Яндекс Форма ─ HTTP-запрос ─► заявка на GitHub
       (вход через my.msu.ru)                     │
                  │                               │ workflow «Подписи»
            выгрузка CSV                          │
                  ▼                               ▼
        tools/import_form.py ────────────► signatures.csv
                                                  │ workflow «Сайт и PDF»
                                                  ▼
                                          новый PDF и сайт
```

Главное: **`signatures.csv` — единственный список подписей**, а сайт и PDF
каждый раз собираются из него заново. Каждая подпись — отдельный коммит,
поэтому вся история видна и проверяема. Подпись через GitHub появляется на
сайте и в PDF примерно через 2–3 минуты.

## Запуск (один раз, минут 20)

### 1. Отдельный публичный репозиторий

Этот репозиторий приватный и содержит личные материалы — публиковать его
нельзя. А заявки-подписи от посторонних и бесплатный GitHub Pages возможны
только в публичном репозитории. Поэтому папку `manifesto/` нужно перенести в
отдельный публичный репозиторий; её содержимое — уже готовый корень такого
репозитория (вместе с `.github/`).

1. На github.com нажмите **New repository**, имя `msu-ai-manifesto`,
   **Public**, без README и лицензии.
2. В клоне этого репозитория, на ветке, где есть папка `manifesto`:

   ```bash
   git subtree split --prefix=manifesto -b manifesto-public
   git push https://github.com/NeuroWorknotNeo/msu-ai-manifesto.git manifesto-public:main
   git branch -D manifesto-public
   ```

Дальше работайте в новом репозитории: туда робот коммитит подписи.

Если назвали репозиторий иначе — поправьте `github_repo` в `config.toml` и
выполните `python3 tools/build.py issue-form`, чтобы ссылки в форме подписи
вели куда надо.

### 2. Настройки нового репозитория

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
   Первый автоматический запуск «Сайт и PDF» после push упадёт на шаге
   публикации, пока Pages не включён, — это нормально.
2. **Actions → «Сайт и PDF» → Run workflow.** Через пару минут сайт
   откроется по адресу `https://neuroworknotneo.github.io/msu-ai-manifesto/`.
3. Если workflow «Подписи» когда-нибудь упадёт с ошибкой 403 на `git push`:
   **Settings → Actions → General → Workflow permissions → Read and write
   permissions.**

### 3. `config.toml`

- `organizer` и `contact` — **заполните до начала сбора подписей.** Это
  организатор, который отвечает за данные подписавших, и способ с ним связаться:
  они попадут на страницу согласия и в PDF. Контакт можно указать
  Telegram-аккаунтом или адресом почты.
- `form_url` — ссылка на Яндекс Форму, когда она будет готова (см. ниже).
  Пока поле пусто, кнопка «Подписать» ведёт в форму на GitHub.

После правки — commit и push: сайт пересоберётся сам.

### 4. Проверка на себе

Откройте сайт, подпишите через GitHub, дождитесь ответа робота в заявке и
новой строки в списке. Потом удалите тестовую подпись: уберите строку из
`signatures.csv` и сделайте коммит.

## Подписи без GitHub: Яндекс Форма

У большинства студентов нет аккаунта на GitHub, поэтому основной способ
подписи — Яндекс Форма. У каждого студента МГУ уже есть учётная запись Яндекса
в домене my.msu.ru, форма работает в России без VPN и не требует регистрации,
а данные хранятся в России.

### Как сделать форму

Создайте форму на [forms.yandex.ru](https://forms.yandex.ru). Заголовки
вопросов важны: по ним скрипт импорта узнаёт столбцы.

| Вопрос | Тип | Обязательный |
|---|---|---|
| Имя и фамилия | короткий ответ; подсказка: «Так подпись будет выглядеть в списке. Можно сокращённо: Иван И.» | да |
| Факультет | выпадающий список: названия из `options.toml` (их удобно скопировать из `.github/ISSUE_TEMPLATE/podpis.yml`) | да |
| Другое подразделение | короткий ответ; показывать, если выбрано «Другое подразделение или филиал МГУ» | нет |
| Курс или статус | выпадающий список: `label` статусов из `options.toml` | да |
| Согласие | флажок: «Я согласен(на) на публикацию имени, факультета, курса и даты подписи в открытом списке подписавших» и ссылка на `…/consent.html` | да |

В настройках формы включите **доступ только для авторизованных
пользователей** и **запрет повторного заполнения**, а в описании попросите
входить через университетскую почту my.msu.ru. Тогда в ответах будет видно,
кто из подписавших действительно из МГУ, — эти данные видят только
организаторы, в публичный список они не попадают.

Ссылку на форму впишите в `form_url` в `config.toml`.

### Как подписи попадают в список: вручную

Надёжный способ, пара минут раз в день:

1. В Яндекс Формах: **Ответы → Выгрузить → CSV**.
2. В клоне публичного репозитория:

   ```bash
   python3 tools/import_form.py ~/Downloads/answers.csv            # посмотреть, что добавится
   python3 tools/import_form.py ~/Downloads/answers.csv --write    # записать
   git add signatures.csv && git commit -m "Подписи из формы" && git push
   ```

Скрипт читает только имя, факультет, курс, согласие, номер и время ответа;
почту и логины не трогает. Повторный импорт той же или более новой выгрузки
безопасен: уже добавленные ответы пропускаются.

### Как подписи попадают в список: автоматически

Яндекс Формы умеют после каждого ответа отправлять HTTP-запрос. Если направить
его в GitHub, из ответа сразу получится заявка, и робот обработает её так же,
как подпись через GitHub.

1. **Токен.** GitHub → Settings → Developer settings → Personal access tokens →
   **Fine-grained tokens → Generate new token**. Repository access: *Only
   select repositories* → `msu-ai-manifesto`. Permissions: **Issues — Read and
   write**, больше ничего. Срок действия — например, 90 дней.
2. **Переменная.** В публичном репозитории: Settings → Secrets and variables →
   Actions → **Variables → New repository variable**: имя `FORM_BOT_LOGIN`,
   значение — ваш логин на GitHub (от его имени интеграция создаёт заявки).
3. **Интеграция.** В форме: **Интеграции → HTTP-запрос**:
   - метод `POST`, адрес
     `https://api.github.com/repos/NeuroWorknotNeo/msu-ai-manifesto/issues`;
   - заголовки `Authorization: Bearer <токен>`,
     `Accept: application/vnd.github+json` и `User-Agent: msu-ai-manifesto-form`
     (без `User-Agent` GitHub отвечает ошибкой 403);
   - тело в формате JSON: `title` — «Подпись из формы», `body` — строки
     ниже, где вместо `…` вставлены ответы (кнопка переменных в редакторе
     интеграции):

     ```
     Имя: …
     Факультет: …
     Другое подразделение: …
     Курс: …
     ID ответа: …
     ```

     Почту в тело **не добавляйте**: заявки на GitHub публичны.
4. Отправьте тестовый ответ: должна появиться и через пару минут закрыться
   заявка, а подпись — появиться на сайте.

Если какой-то запрос не дойдёт (например, GitHub временно ограничит частоту
запросов), ответ не потеряется: он остаётся в Яндекс Формах, и ручной импорт
его подберёт, не создав дублей.

## Проверка и удаление подписей

- **Через GitHub** с одной учётной записи можно подписать один раз; робот
  проверяет имя, факультет, курс и согласие и объясняет в заявке, что не так.
- **Через форму** проверка — вход через my.msu.ru. Руководству можно показать
  сводку вроде «из N подписей M оставлены из учётных записей my.msu.ru».
- **Удалить подпись** (по просьбе подписавшего или если она явно фальшивая):
  уберите строку из `signatures.csv`, сделайте commit и push. Если подпись
  пришла через GitHub, удалите и заявку: внизу её страницы есть кнопка
  **Delete issue**. На странице согласия обещано удалять подпись в течение
  трёх рабочих дней, а по просьбе — и из истории репозитория (это делается
  через `git filter-repo`; если понадобится, попросите Claude помочь).
- Добавить подпись вручную: строка в `signatures.csv` с `id` вида `m-1`,
  `source` = `manual` и пустым `account`.

## Правка текста

- Текст — `text/manifesto.md`, приложение — `text/appendix.md`, согласие на
  публикацию — `text/consent.md`. Разметка — Markdown: заголовки `##`,
  `**полужирный**`, `*курсив*`, ссылки, сноски `[^метка]` с определением
  `[^метка]: …`, списки и таблицы. Неразрывные пробелы после предлогов и
  перед тире расставляются сами.
- **Когда подписи уже собираются, текст лучше не менять:** люди подписали
  конкретную редакцию. Если без правки не обойтись, увеличьте `edition` и
  поменяйте `edition_date` в `config.toml`; прежние редакции останутся в
  истории git.
- Факультеты и статусы — в `options.toml`. После правки выполните
  `python3 tools/build.py issue-form` и закоммитьте обновлённую форму.
- Вёрстка PDF — `manifesto.typ`, сайт — `site/`.

Собрать локально (нужен Python 3.11+):

```bash
pip install -r requirements.txt
python3 tools/build.py              # build/manifesto.pdf и build/site/index.html
python3 tools/build.py --snapshot   # то же и обновить manifesto.pdf в корне
python3 -m unittest discover -s tests
```

## Распространение

- Ссылку на сайт — в чаты курсов и факультетов, в Telegram и ВКонтакте:
  на сайте есть кнопки «Поделиться».
- PDF можно распечатать и повесить на факультете: QR-код в плашке «Поддержите
  предложение» ведёт на сайт. Отдельный QR-код для плакатов —
  `…/qr.svg` на сайте.
- Преподаватели, сотрудники и выпускники могут подписать тоже: они попадают в
  отдельный список «Поддержали». Их поддержка особенно весома.
- Стоит заранее поговорить со студенческим советом и профкомом: они могут
  поддержать инициативу и передать манифест официально.

## Как передать манифест руководству

Когда подписей наберётся достаточно, распечатайте свежий PDF со списком и
передайте его официально: через канцелярию ректората, через
[электронную приёмную МГУ](http://www.question.msu.ru/) или через
студенческий совет. К обращению полезно приложить сводку проверки подписей
(см. выше) и контакты организаторов.

## Юридические моменты

Это не юридическая консультация, а то, что учтено в устройстве сбора подписей.

- **Персональные данные (152-ФЗ).** Публикация имени требует согласия на
  распространение персональных данных. Поэтому в обеих формах есть
  обязательная галочка, а на сайте — отдельная страница согласия
  (`text/consent.md`): что публикуется, зачем, кто отвечает и как отозвать
  подпись. Для этого нужны `organizer` и `contact` в `config.toml`.
- **Минимум данных.** Публикуются только подпись в том виде, в каком её
  написал человек (можно «Иван И.»), факультет, курс и дата. Почта и логины
  не публикуются никогда.
- **Где хранятся данные.** Основной канал — Яндекс Форма: сами ответы
  хранятся в России. На GitHub попадает только то, что подписавшие разрешили
  опубликовать.
- **Тон.** Манифест — просьба и предложение, без требований и политических
  заявлений. Сайт прямо говорит, что это студенческая инициатива, а не
  официальный документ МГУ.

## Если что-то пошло не так

- **Сайт не открывается из России.** GitHub Pages обычно доступен без VPN.
  Если нет, сайт — это просто папка `build/site`: её можно выложить на любой
  хостинг, например в Yandex Object Storage, и указать новый адрес в
  `site_url`.
- **Подпись через GitHub не появилась.** Actions → «Подписи»: там видно,
  что решил робот. Если заявок пришло сразу много, GitHub может отменить часть
  запусков в очереди — раз в час робот запускается по расписанию и подбирает
  всё, что осталось.
- **Workflow по расписанию отключился.** GitHub выключает такие запуски после
  60 дней без активности в репозитории; включить обратно — Actions → «Подписи»
  → Enable workflow.
